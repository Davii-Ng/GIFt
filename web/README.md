# gifly

A local semantic GIF search website with account-based favorites. The website and API run together at **http://127.0.0.1:8000**. Search uses the local Chroma index and accounts and favorites use Firebase Authentication and Cloud Firestore.

## Start the website

From the GIFt-main project root:

```powershell
.\start-web.ps1
```

Pass `-PythonPath` to select an existing Python environment, or `-Port 8010` to serve the complete website and API at http://127.0.0.1:8010. The default is 8000. Each port can have only one server listening; stop the previous instance before reusing its port.

Open http://127.0.0.1:8000 (or http://localhost:8000). Log in or sign up using the popup in the header. Clicking a heart while logged out opens the same popup; after login, the selected GIF is saved. Each account has its own favorites. Registration signs in immediately. Usernames use 3–24 letters, numbers or underscores and are case-insensitive; passwords use 8–128 characters.

Errors, warnings and system confirmations are logged in the browser's **F12 → Console**, prefixed `[gifly:context]`; they are not displayed in banners, toasts or form error messages. Validation still blocks invalid input. Normal loading/progress and the end-of-search message remain visible.

If PowerShell blocks scripts, run this command from the project root to bypass the policy for that invocation only:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-web.ps1 -Port 8000
```

Accounts use Firebase Authentication and favorites use Cloud Firestore. See [Firebase setup](../FIREBASE_SETUP.md) before enabling accounts. Guest search works while configuration is pending.

## Search modes

Choose **GIFs** or **Videos** in the search form. GIF results include feedback controls. With an empty search box, likes recommend similar GIFs and dislikes hide cards from the home feed. The home feed shuffles on every page load and keeps the same order while you load more. Home feedback is stored separately in the current browser. Dislikes still hide GIFs in a shuffled feed, while likes influence recommendations when you vote.

- **GIF search** selects a local search method automatically. Wrap a phrase in quotation marks to prioritize exact matches. For ordinary searches MiniLM is the fallback when a benchmark group has too few queries or another method fails to improve quality within the latency budget. Like/dislike reranks the full index using the existing Rocchio weights. Dislikes for similar searches stay in the current browser. Reset undoes votes for the current search, and Show hidden GIFs again clears remembered dislikes matching its meaning.
- **Load more** appends further search results without clearing the query or votes. Results are ordered by relevance with a ×1.02 weight for public community GIFs and ×1.0 for catalog GIFs. Only positive similarities are returned; a final click displays the end-of-results message when none remain. The 60-result request limit is a page limit, not a total cap.
- **Create GIF / Your contribution** supports video uploads, trimming, cropping, rotation and fixed 480p GIF output. Public names and descriptions are searchable; private media is restricted to its owner. Click a ready contribution's visibility badge to switch Public/Private. See [the contribution guide](CONTRIBUTIONS.md) for the full workflow and limits.
- **Gemini GIF feedback API** uses the GIF index produced by `python -m gift.gemini.index`. Install `google-genai`, set `GEMINI_API_KEY` in the server environment and restart. Queries in this mode are sent to Gemini.
- **Video search** uses the local clips in `data/videos/inbox` and vectors generated by `python -m gift.video.embed`. It uses the same Gemini setup to embed query text. Search results can play compatible clips in the browser.
- **Automatic benchmark** runs in the background when the catalog fingerprint, benchmark data or policy version changes. It compares semantic, BM25 and hybrid ranking on the frozen evaluation set and measures keyword overhead on the live catalog. See `.cache/auto-search.json` in the web folder for methods and scores. Searches work with the semantic fallback while the benchmark runs.
- **Developer benchmarks** are available through the [benchmark CLI](../benchmark/README.md) and the tool endpoints in `/docs`.

## Local storage

- `.chroma/`: persistent semantic search index.
- `.cache/models/`: cached MiniLM model.
- Firestore stores favorites under users/{uid}/favorites. Existing SQLite files are retained locally for a future migration.
- `.local/contributions/`: per-UID contribution metadata/jobs in SQLite, generated GIF files, temporary uploads and the separate public Chroma index. Back up this entire directory. `CONTRIBUTION_DATA_DIR` overrides it.
- `data/tgif.json`: the full prepared catalog.

The original TGIF file contains **125,782 descriptions for 102,068 unique GIF URLs**. Preparation preserves every distinct description, merging descriptions that refer to the same GIF so results do not contain duplicate images. The entire catalog is indexed and searchable; the browser loads only a page at a time. It does not load all GIF images into memory.

The search catalog, vector index and created GIF files are local to the server; Firebase holds account identities, favorites and mirrored contribution metadata. **Catalog GIF images still load from their original internet URLs**. Some older TGIF URLs may be unavailable. The site retains the description and original link when an image fails and logs the error to Console. Download is available inside the GIF preview, with bounded server fetching for sources that do not allow browser CORS.

## First-time installation or rebuilding the full index

Run from the project root with Python 3.11 or 3.12. The catalog preparation command downloads the shared TGIF TSV when needed.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m web.prepare_tgif
.\start-web.ps1 -IndexData
```

Stop the server before preparing or indexing new data. Preparation defaults to the full dataset; use `--limit` only to deliberately select fewer unique GIFs. Indexing is resumable and skips unchanged records. The first run needs internet to download the model; later searches use the local cache.

`GIF_DATA_PATH` and `GIF_DB_PATH` can override the catalog and index paths; use the same settings for preparation, indexing and serving.

VS Code Live Server on port 5500 or 5501 can preview the frontend while `start-web.ps1` runs the Python API on port 8000. These preview ports forward API requests to port 8000; authorize the frontend hostname in Firebase and use the same hostname for preview and API. Port 5500 alone serves static files and does not perform search or video conversion. The complete application is simplest to use directly on port 8000. Favorites previously kept in browser localStorage are not assigned automatically to new accounts.

## API

- `GET /api/health`: readiness, unique GIF count and original description count.
- `GET /api/catalog?limit=24&offset=0`: paginated catalog; optional category or up to 60 repeated `ids` parameters.
- `GET /api/search?q=a+confused+dog&limit=24`: semantic results across the complete local index.
- `POST /api/tools/feedback`: GIF search and relevance feedback; add `offset` to request a positive-only, relevance-ordered page with `next_offset` and `has_more`.
- `GET /api/gifs/{id}/download`: download a known catalog GIF or an accessible contribution.
- Accounts and favorites use the Firebase browser SDK and per-user Firestore rules; the legacy SQLite HTTP account routes are not enabled in this checkout.
- `GET /api/contributions`: the signed-in user's GIFs, authenticated with a Firebase bearer token.
- See [Create GIF and Your contribution](CONTRIBUTIONS.md) for upload, rendering, media access, ownership and public search endpoints.

The MiniLM model embeds descriptions into 384 dimensions. Chroma ranks results by cosine similarity. Scores are ranking measures, not accuracy percentages. TGIF has no category labels, so category filters are hidden for that dataset. Account files, model cache and search database are not served as public files.

## Tests

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s web/tests -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test web/tests/api-client.test.mjs web/tests/firebase-account.test.mjs web/tests/contributions.test.mjs web/tests/gif-actions.test.mjs web/tests/system-log.test.mjs
```

Tests use separate temporary databases. They cover the retained SQLite account store, Firebase error formatting, contribution ownership and media access, real video-to-GIF conversion, metadata normalization and vector migration, public/private switching, merged feedback search, positive-only pagination beyond 60 results, downloads, console-only logging, cross-origin protection and repeatable indexing. Browser smoke checks use a separate synthetic preview and do not change real account records or visibility settings.
